## 三、错误处理最佳实践

### 前端错误处理建议

1. **统一错误拦截**
   - API 响应拦截（`utils/api.js`）
   - Socket 错误监听
   - 路由守卫错误

2. **错误展示方式**
   - 使用 Element Plus 的 `ElMessage` 提示
   - 表单错误在输入框下方显示
   - 严重错误使用弹窗提示

3. **错误日志记录**
   - 前端错误日志（开发环境）
   - 发送到后端日志系统（生产环境）

### 后端错误处理建议

1. **统一错误格式**
```javascript
{
  success: false,
  message: "错误描述",
  code: "ERROR_CODE", // 可选
  details: {} // 可选，详细错误信息
}
```

2. **错误日志记录**
   - 使用 Winston 记录错误详情
   - 记录请求参数、用户信息、时间戳
   - 敏感信息脱敏

3. **错误分类处理**
   - 400：客户端错误，明确告知用户如何修正
   - 401/403：认证授权错误，引导登录或申请权限
   - 404：资源不存在，提供返回或搜索
   - 500：服务器错误，不暴露技术细节，引导联系管理员

## 四、错误文案写作原则

### 武侠风格指南

1. **称呼**
   - 用户：大侠、少侠、女侠、掌门、长老
   - 管理员：掌门、长老、护法
   - 普通用户：侠客、同道中人

2. **场景隐喻**
   - 登录：进入江湖、踏入武林
   - 注册：初入江湖
   - 退出：离开江湖
   - 封禁：禁止进入江湖、逐出武林
   - 禁言：封住嘴巴、禁止发言
   - 网络错误：江湖失联、信号中断
   - 服务器：茶楼、客栈、聚贤庄

3. **语言风格**
   - 友好、幽默但不失尊重
   - 避免过于技术化
   - 清晰传达问题和解决方案

### 通用原则

1. **清晰明确**：用户一看就知道什么问题
2. **提供解决方案**：告诉用户下一步该怎么做
3. **避免责备**：不把问题归咎于用户
4. **保持一致性**：术语和风格统一
5. **适度情感**：友好但不过分卖萌

## 六、错误监控与优化

### 监控指标

1. **错误率**：错误请求数 / 总请求数
2. **错误类型分布**：各类错误占比
3. **错误时间分布**：高峰期/低峰期
4. **用户影响范围**：受影响用户数

### 优化建议

1. **预防性验证**：前端提前校验，减少无效请求
2. **友好降级**：服务不可用时提供替代方案
3. **自动重试**：网络错误自动重试（最多 3 次）
4. **错误上报**：严重错误自动上报给管理员
5. **用户反馈**：提供错误反馈渠道

## 七、常用工具函数

### 前端错误处理工具

```javascript
// utils/errorHandler.js
export function handleError(error, context = '') {
  const messages = {
    '网络错误': '江湖暂时失联，请检查网络连接',
    '请求超时': '请求发送太久，请稍后再试',
    '未授权': '请先登录',
    '权限不足': '您的权限不足以执行此操作',
    '服务器错误': '江湖出现异动，请稍后再试'
  }
  
  const message = error.message || error.data?.message || '未知错误'
  const friendlyMessage = messages[message] || message
  
  if (context) {
    ElMessage.error(`${context}：${friendlyMessage}`)
  } else {
    ElMessage.error(friendlyMessage)
  }
  
  // 记录错误日志
  console.error('[Error]', context, error)
}
```

### 后端错误处理中间件

```javascript
// middleware/errorHandler.js
module.exports = (err, req, res, next) => {
  logger.error('请求错误', {
    method: req.method,
    path: req.path,
    error: err.message,
    stack: err.stack,
    user: req.user?.id
  })
  
  res.status(err.status || 500).json({
    success: false,
    message: process.env.NODE_ENV === 'production' 
      ? '服务器内部错误' 
      : err.message
  })
}
```
