# 在线状态保持与泡点经验保存需求文档

## 问题描述

当前实现存在以下问题：
1. 用户点击导航链接离开聊天室页面时，Vue 组件卸载触发 `onUnmounted()`，调用 `disconnectSocket()` 断开 Socket 连接
2. Socket 断开导致用户从 `online_users` 表被删除，显示为离线状态
3. 用户无法在其他页面浏览时继续获得泡点经验
4. 泡点经验仅在发送聊天消息时更新，缺乏独立的在线时长统计机制

## 需求规格

### 1. 全局 Socket 连接管理

**R1.1** - Socket 连接生命周期应与用户登录会话绑定，而非与页面组件绑定
- 用户登录后建立 Socket 连接
- 用户主动退出登录时才断开 Socket 连接
- 页面切换时保持 Socket 连接不断开

**R1.2** - Socket 实例应存储在单例模块中，避免重复连接
- 整个应用生命周期内只维护一个 Socket 实例
- 所有页面共享同一个 Socket 连接

### 2. 在线状态保持

**R2.1** - 用户在应用内任意页面时，都应保持在线状态
- `online_users` 表记录不应因页面切换而被删除
- 用户在不同页面间导航时，在线状态持续保持

**R2.2** - 心跳机制检测真实在线状态
- 前端定期（建议 30 秒）发送心跳信号
- 后端更新 `last_active_at` 时间戳
- 后端定时清理超时未心跳的用户（建议 3-5 分钟无心跳视为离线）

### 3. 泡点经验自动保存

**R3.1** - 独立的在线时长统计机制
- 泡点经验不应依赖聊天消息发送
- 基于在线时长自动累计经验值
- 支持配置每分钟/每小时经验获取速率

**R3.2** - 经验数据定期保存
- 前端每 1-2 分钟同步一次经验数据到 UI
- 后端实时更新数据库中的经验值
- 防止数据丢失（网络断开、页面关闭等情况）

**R3.3** - 经验获取上限控制
- 保留现有的每日经验上限机制
- 达到上限后停止累计，但不影响在线状态
- 前端显示当前经验获取进度

### 4. 用户体验优化

**R4.1** - 页面切换无感知
- 用户在不同页面导航时，聊天室 Socket 连接保持
- 返回聊天室页面时消息列表保持最新状态

**R4.2** - 经验获取可视化
- 在聊天室页面显示当前泡点经验获取速率
- 显示今日已获得经验值和剩余可获取经验值
- 经验值变化时给予视觉反馈

**R4.3** - 离线重连机制
- 网络异常断开后自动重连
- 重连后恢复在线状态和经验累计

### 5. 管理员监控

**R5.1** - 后台可查看真实在线用户
- 区分"应用内在线"和"聊天室活跃"状态
- 显示用户最后活跃时间

**R5.2** - 经验获取统计
- 可查看用户泡点经验获取记录
- 支持导出经验获取日志

## 约束条件

1. **向下兼容**：不影响现有聊天功能和命令系统
2. **性能要求**：心跳和数据同步不应造成明显的服务器负载
3. **数据库兼容**：保持 MySQL 5.7 兼容
4. **前端框架**：继续使用 Vue 3 + Composition API
5. **安全要求**：心跳和经验同步需要 JWT 认证

## 验收标准

1. ✅ 用户在应用内任意页面停留 5 分钟，在线状态持续保持
2. ✅ 用户离开聊天室页面后，5 分钟内可获得完整的泡点经验
3. ✅ 页面切换时 Socket 连接不断开，无重连日志
4. ✅ 主动退出登录时，在线状态正确清除
5. ✅ 后端能正确清理超时未心跳的"僵尸"连接
6. ✅ 前端显示的经验数据与数据库实际值一致
7. ✅ 网络断开恢复后，自动重连并继续累计经验

## 优先级

| 优先级 | 需求 | 说明 |
|--------|------|------|
| P0 | 全局 Socket 管理 | 核心基础，其他功能依赖 |
| P0 | 在线状态保持 | 解决用户核心痛点 |
| P0 | 泡点经验自动保存 | 核心功能 |
| P1 | 心跳机制 | 保障在线状态准确性 |
| P1 | 经验获取可视化 | 用户体验提升 |
| P2 | 离线重连 | 增强稳定性 |
| P2 | 管理员监控 | 运营需求 |
